# RisuAI Lua 스크립팅

RisuAI는 캐릭터 카드와 모듈이 명확히 정의된 수명 주기(사용자 입력, LLM 출력, 채팅 시작, 버튼 클릭, 메시지 편집 훅 등)에 Lua 스크립트를 실행할 수 있도록 지원한다. 스크립트는 브라우저 탭 내 샌드박스 환경인 Wasmoon(WebAssembly로 컴파일된 Lua 5.4)에서 실행되며, 고정된 호스트 주입 함수(Host-injected functions) 세트를 통해 RisuAI 내부로 콜백을 보낸다.

이 문서는 RisuAI Lua 작성자를 위한 API 레퍼런스이다. 아래 나열된 모든 함수는 `src/ts/process/scriptings.ts`를 기준으로 검증되었다. 함수 세트는 닫혀 있으며, RisuAI는 `json`과 표준 Lua 라이브러리 외에 임의의 Lua 라이브러리를 로드하지 않는다. 존재하지 않는 호스트 함수를 임의로 호출해서는 안 된다.

---

## 1. 스크립트 실행 방식

### 1.1 진입점 (Entry point)

Lua "트리거 스크립트(Trigger script)"는 캐릭터(`character.triggerscript[]`) 또는 모듈에 첨부된다. RisuAI 런타임은 수명 주기 이벤트의 이름과 일치하는 최상위 함수를 호출하여 스크립트를 실행한다.

| 모드 (이벤트)   | RisuAI가 호출하는 함수                      | 인수 (Args)                           |
|-----------------|---------------------------------------------|---------------------------------------|
| `input`         | `onInput(id)`                               | `id` = 액세스 키                      |
| `output`        | `onOutput(id)`                              | `id`                                  |
| `start`         | `onStart(id)`                               | `id`                                  |
| `onButtonClick` | `onButtonClick(id, data)`                   | `id`, `data` (버튼 페이로드 문자열)   |
| `editInput`     | `listenEdit('editInput', cb)` 콜백으로 전달 | 각 cb는 `(id, value, meta)`를 받음    |
| `editOutput`    | `listenEdit('editOutput', cb)` 콜백으로 전달| `(id, value, meta)`                   |
| `editDisplay`   | `listenEdit('editDisplay', cb)` 콜백으로 전달| `(id, value, meta)`                  |
| `editRequest`   | `listenEdit('editRequest', cb)` 콜백으로 전달| `(id, value, meta)`                  |
| 커스텀 이름     | `<모드_이름>(id)`                           | `id` — 해당 모드 이름의 전역 함수     |

`id` 매개변수는 액세스 키(UUID)이며, 모든 호스트 호출에 스레드처럼 전달해야 한다. 다른 값을 전달하면 호스트는 대부분의 호출을 무시한다.

### 1.2 엔진 수명 주기

- 모드(Mode) 문자열당 하나의 영구적인 Lua 엔진이 유지되며, 호출 간에 상태가 보존된다.
- 스크립트 소스 코드가 변경되면 엔진이 처음부터 다시 빌드된다.
- 호출은 모드별로 직렬화(뮤텍스)된다. 동일한 모드의 두 호출이 동시에 실행되지 않는다.
- 런타임은 사용자의 코드 실행 전에 Lua JSON 라이브러리인 `json`을 자동으로 `require`하므로, 전역에서 즉시 사용할 수 있다.
- 런타임은 원시 호스트 API 위에 래퍼 레이어(Wrapper layer; `getChat`, `LLM`, `setState`, `listenEdit`, `async`, `callListenMain` 등)를 주입한 뒤, 그 아래에 사용자의 코드를 덧붙인다. 즉, 사용자는 해당 헬퍼 함수들을 직접 정의하지 않고도 사용할 수 있다.

### 1.3 권한 (액세스 티어)

모든 호스트 함수는 `id`를 검사하여 액세스 권한을 확인한다.

| 티어        | 부여 조건                     | 허용되는 작업 |
|-------------|-------------------------------|-----------------|
| **Open**    | 항상 부여됨                   | 읽기 전용 액세스: `getChatMain`, `getChatLength`, `getName`, `getPersonaName` 등 조회 및 로깅 함수 |
| **Safe**    | `lowLevelAccess=false`이며 `editDisplay`가 아닌 모드 | Open의 모든 권한 + 상태 쓰기: `setChat`, `addChat`, `setChatVar`, `stopChat`, `alertError` 등 데이터 수정 함수 |
| **EditDisplay** | `mode = 'editDisplay'`인 경우 | 제한된 쓰기: `setChatVar`, 알림(alerts)만 허용. 다른 상태 쓰기 API는 아무런 효과 없이 반환됨. |
| **LowLevel**| 트리거에 `lowLevelAccess=true`가 설정된 경우 | `LLMMain`, `axLLMMain`, `simpleLLM`, `request`, `similarity`, `generateImage`, `loadLoreBooksMain` 등 비용이 발생하는 작업 |

권한 거부는 **조용히(Silent) 처리**된다. Safe 권한 없이 `setChat`을 호출하면 오류를 발생시키지 않고 `nil`을 반환한다. 항상 스크립트가 실제로 실행될 모드에서 권한을 테스트해야 한다.

### 1.4 비동기 (Async / Promise)

다수의 호스트 함수는 비동기 함수(JS Promise 반환)이다. Wasmoon은 Promise에 `:await()` 메서드를 제공한다. 래퍼 레이어는 일반적인 함수들(`LLM`, `axLLM`, `loadLoreBooks`, `getCharacterImage`, `getPersonaImage`)에 이미 `:await()` 처리를 해두었으므로 직접 작성할 필요가 없다. 
다만 문서에서 `[await]`로 표시된 함수(예: `getTokens`, `request`, `generateImage`, `simpleLLM`, `hash` 등)는 반환된 Promise에 `:await()`를 호출해야 한다.

```lua
local n = getTokens(id, "hello"):await()
local resp = request(id, "https://example.com"):await()
local body = json.decode(resp).data
```

직접 비동기 함수를 작성해야 할 경우(예: `listenEdit` 콜백 내에서 비동기 작업을 대기할 때), 제공되는 `async()` 헬퍼로 감싸야 한다.

```lua
listenEdit('editOutput', async(function(id, value, meta)
    local toks = getTokens(id, value):await()
    return value .. "\n[tokens: " .. toks .. "]"
end))
```

### 1.5 반환값 규칙

| 훅 (Hook)                            | 반환 동작 (Return semantics) |
|--------------------------------------|------------------|
| `onInput`, `onOutput`, `onStart`     | 리터럴 `false`를 반환하면 `stopSending = true`가 설정되어 메시지가 취소된다. 그 외의 반환값은 무시된다. (채팅을 수정하려면 `setChat`/`addChat` 등을 사용하라.) |
| `onButtonClick(id, data)`            | 반환값은 호출자에게 트리거 결과의 `res` 필드로 전달된다. |
| `listenEdit` 콜백들                  | 체인(Fold-left) 방식으로 동작한다. 각 콜백은 이전 콜백의 반환값을 `value`로 받는다. 새로운 값(텍스트는 문자열, 채팅 배열은 테이블)을 반환해야 한다. 최종 반환값이 원본 콘텐츠를 대체한다. |
| 커스텀 모드 함수 (`<mode>(id)`)      | `onInput`과 동일 (`false`는 중지, 나머지는 무시). |

## 2. `id` 매개변수

모든 호스트 함수는 첫 번째 인자로 `id`(액세스 키)를 취한다. 수명 주기 훅에서 받은 `id`를 항상 전달해야 한다. 래퍼 레이어의 헬퍼 함수들(`getChat(id, idx)`, `setState(id, name, value)` 등)도 동일한 패턴을 따른다.

```lua
function onInput(id)
    local last = getChat(id, getChatLength(id) - 1)
    log(last)  -- log()는 인자를 하나만 받음 (예외)
    setChatVar(id, "last_input_role", last.role)
end
```

## 3. 타입 연결 (Type bridging: JS ↔ Lua)

- 문자열, 숫자, 불리언, `nil`은 양방향으로 투명하게 변환된다.
- 테이블 / 배열 / 객체와 같은 복잡한 데이터는 JSON 문자열로 변환되어 교환된다. 일반 API(채팅, LLM, 로어북, 상태)에 대해서는 래퍼 레이어가 인코딩/디코딩을 자동으로 처리한다. 원시(Raw) `*Main` 함수를 사용할 때는 직접 `json.decode()`를 해야 한다.
- Promise: `:await()`를 호출하여 값을 확인한다.
- 호스트 함수에 전달되는 Lua 테이블(예: `setFullChat`, `LLM`, `upsertLocalLoreBook`)은 래퍼에 의해 JSON으로 인코딩되며, 호스트가 이를 다시 파싱한다.

주입된 `json` 라이브러리 사용법:
```lua
json.encode(value)   -- 테이블 → 문자열
json.decode(str)     -- 문자열 → 테이블 | nil
```

## 4. 빠른 시작 (Quick start)

### 4.1 모든 사용자 메시지 로깅하기
```lua
function onInput(id)
    local len = getChatLength(id)
    local last = getChat(id, len - 1)
    log("사용자가 보낸 메시지: " .. last.data)
end
```

### 4.2 금지어 포함 시 메시지 거부하기
```lua
function onInput(id)
    local len = getChatLength(id)
    local last = getChat(id, len - 1)
    if string.find(last.data, "금지어", 1, true) then
        alertError(id, "허용되지 않는 단어입니다.")
        return false  -- 메시지 전송 취소
    end
end
```

### 4.3 `editOutput`을 이용해 어시스턴트 응답 수정하기
```lua
listenEdit('editOutput', function(id, value, meta)
    -- value는 어시스턴트의 텍스트, meta는 훅 전용 추가 데이터
    return value:gsub("알겠습니다", "물론이죠")
end)
```

## 5. 수명 주기 이벤트 레퍼런스

### 5.1 `onInput(id)`
사용자가 메시지를 제출한 후, LLM 호출 이전에 실행된다. 이 시점에 새로운 사용자 메시지는 이미 채팅에 추가되어 있다. 메시지를 취소하려면 `false`를 반환한다.

### 5.2 `onOutput(id)`
LLM이 응답을 생성한 후, 사용자에게 표시/스트리밍되기 전에 실행된다. 새로운 어시스턴트 메시지는 이미 채팅에 추가되어 있다. 채팅 진행을 취소하려면 `false`를 반환한다.

### 5.3 `onStart(id)`
채팅 세션이 초기화될 때(예: 새 채팅을 열 때) 실행된다. 첫 인사 메시지 외에는 아직 문맥이 없다.

### 5.4 `onButtonClick(id, data)`
사용자가 CBS 생성 버튼(`{{button::Label::trigger_payload}}`)을 클릭할 때 실행된다. `data` 인수는 `trigger_payload`와 동일하다.

### 5.5 `listenEdit(type, callback)` — 4가지 편집 훅

| `type`         | 실행 시점                                        | `value`의 형태                                |
|----------------|--------------------------------------------------|-----------------------------------------------|
| `editInput`    | 사용자 입력이 처리되기 전                        | 사용자 메시지 문자열                          |
| `editOutput`   | LLM 출력 후, 화면 표시 및 저장 전                | 어시스턴트 메시지 문자열                      |
| `editRequest`  | 요청 페이로드가 모델로 전송되기 전               | OpenAI 스타일의 채팅 배열 (`{role, content}` 테이블 배열) |
| `editDisplay`  | 메시지가 화면에 렌더링될 때                      | 렌더링 중인 메시지 문자열                     |

콜백 시그니처는 `function(id, value, meta) → modifiedValue` 이다. 체인 규칙에 따라 콜백은 등록 순서대로 호출되며, 반드시 값을 반환해야 한다. `nil`을 반환하면 체인이 끊어진다.

## 6. 호스트 함수 레퍼런스

표기 일러두기: `[저수준]` = LowLevel 티어, `[안전]` = Safe 티어, `[편집]` = EditDisplay 티어 포함, 표시 없음 = Open 티어. (래퍼(Wrapper) 함수가 있다면 원시 함수 대신 래퍼를 사용하는 것을 권장한다.)

### 6.1 채팅 읽기/쓰기

| 래퍼 함수                                  | 티어   | 반환값                                  | 설명 |
|--------------------------------------------|--------|-----------------------------------------|-------------|
| `getChat(id, index)`                       | 개방   | `{role, data, time}` 테이블             | 단일 메시지 조회. 음수 인덱스 지원(0 → 첫 메시지, -1 → 마지막). |
| `getFullChat(id)`                          | 개방   | `{role, data, time}` 테이블 배열        | 현재 채팅의 전체 메시지. |
| `getChatLength(id)`                        | 개방   | 숫자                                    | 메시지 개수. |
| `setChat(id, index, value)`                | 안전   | —                                       | `index` 위치 메시지의 `data` 교체. |
| `setChatRole(id, index, value)`            | 안전   | —                                       | 역할 설정 (`"user"` 또는 `"char"`). |
| `setFullChat(id, value)`                   | 안전   | —                                       | 메시지 배열 전체 교체. `value`는 `{role, data}`의 Lua 테이블. |
| `addChat(id, role, value)`                 | 안전   | —                                       | 메시지 추가. |
| `insertChat(id, index, role, value)`       | 안전   | —                                       | `index` 위치에 메시지 삽입. |
| `removeChat(id, index)`                    | 안전   | —                                       | 단일 메시지 삭제. |
| `cutChat(id, start, finish)`               | 안전   | —                                       | `[start, finish)` 구간으로 배열 자르기. |
| `getCharacterLastMessage(id)`              | 개방   | 문자열                                  | `"char"` 역할의 가장 최근 메시지. 없으면 첫인사 반환. |
| `getUserLastMessage(id)`                   | 개방   | 문자열                                  | `"user"` 역할의 가장 최근 메시지. 없으면 `""` 반환. |

### 6.2 변수 및 상태

| 래퍼 함수                   | 티어        | 저장소 (Backing store)  | 설명 |
|-----------------------------|-------------|-------------------------|-------|
| `getChatVar(id, key)`       | 개방        | 채팅별                  | 원시 문자열 읽기. |
| `setChatVar(id, key, val)`  | 안전 / 편집 | 채팅별                  | 원시 문자열 쓰기. |
| `getGlobalVar(id, key)`     | 개방        | 전역 (모든 채팅 공통)   | 읽기 전용. |
| `getState(id, name)`        | 개방        | 채팅별 (`__<name>` 키 하위에 JSON 인코딩됨) | JSON 직렬화 가능 값(테이블, 숫자 등) 읽기. |
| `setState(id, name, value)` | 안전 / 편집 | 채팅별                  | 테이블/숫자 등에 권장. 내부적으로 이름 앞에 `__`가 붙음. |

### 6.3 캐릭터 / 페르소나 데이터

| 함수                                           | 티어   | 반환값  | 설명 |
|------------------------------------------------|--------|---------|-------------|
| `getName(id)`                                  | 개방   | 문자열  | 현재 캐릭터의 이름. |
| `setName(id, name)`                            | 안전   | —       | 이름 설정. |
| `getDescription(id)`                           | 안전   | 문자열  | 캐릭터 설명. (그룹 채팅 시 예외 발생) |
| `setDescription(id, desc)`                     | 안전   | —       | 캐릭터 설명 설정. |
| `getCharacterFirstMessage(id)`                 | 개방   | 문자열  | 캐릭터의 첫 인사말. |
| `setCharacterFirstMessage(id, data)`           | 안전   | bool    | 첫 인사말 설정. |
| `getPersonaName(id)`                           | 개방   | 문자열  | 사용자 이름 (설정 기준). |
| `getPersonaDescription(id)`                    | 개방   | 문자열  | 사용자 페르소나 (CBS 파싱됨). |
| `getAuthorsNote(id)`                           | 개방   | 문자열  | 채팅별 작가의 노트. |
| `getBackgroundEmbedding(id)`                   | 안전   | 문자열  | 캐릭터의 HTML 배경. |
| `setBackgroundEmbedding(id, data)`             | 안전   | bool    | HTML 배경 설정. |

### 6.4 로어북 (Lorebook)

| 래퍼 함수                                                     | 티어   | 반환값                                 | 설명 |
|---------------------------------------------------------------|--------|----------------------------------------|-------------|
| `getLoreBooks(id, search)`                                    | 안전   | 로어 항목 배열                         | `comment == search`인 항목 반환 (`content`는 CBS 파싱됨). |
| `upsertLocalLoreBook(id, name, content, options)`             | 안전   | —                                      | 채팅 로컬 로어북을 삽입 또는 교체. |
| `loadLoreBooks(id)`                                           | 저수준 | `{ data, role }` 배열                  | 현재 활성화된 로어북 항목 로드 (자동 `await` 및 JSON 디코딩 적용). |

### 6.5 LLM 호출 (저수준 권한 전용)

다음 함수들은 모두 `{ success = boolean, result = string }` 테이블을 반환한다.

- **`LLM(id, prompt, useMultimodal?, options?)` `[저수준]`**
  메인 모델을 호출한다. `prompt`는 `{role, content}` 배열이다. `useMultimodal`이 `true`이면 텍스트 내의 인레이(inlay) 마커를 추출해 이미지 멀티모달 입력으로 처리한다. `options`에는 `{streaming = true}`를 전달할 수 있으며, 래퍼가 전체 문자열이 완성될 때까지 스트림을 수집한 뒤 반환한다.
- **`axLLM(id, prompt, useMultimodal?, options?)` `[저수준]`**
  `LLM`과 동일하지만 보조 모델(`axmodel`)을 호출한다. 요약이나 분류 작업에 적합하다.
- **`simpleLLM(id, prompt)` `[저수준]` `[await]`**
  문자열 프롬프트 하나만 던지는 단일 턴 호출이다.

## 7. 패턴 및 레시피

*(코드 내 주석 번역)*

### 7.1 전송 전 숨겨진 시스템 메시지 주입하기
```lua
listenEdit('editRequest', function(id, value, meta)
    -- value는 {role, content}의 요청 배열
    table.insert(value, 1, {
        role = "system",
        content = "항상 2인칭으로 대답하라.",
    })
    return value
end)
```

### 7.2 나가는 요청의 토큰 예산 제한하기
```lua
listenEdit('editRequest', async(function(id, value, meta)
    local total = 0
    for _, m in ipairs(value) do
        total = total + getTokens(id, m.content):await()
    end
    if total > 30000 then
        -- 제한에 맞을 때까지 가장 오래된 비시스템 메시지 삭제
        for i, m in ipairs(value) do
            if m.role ~= "system" then table.remove(value, i); break end
        end
    end
    return value
end))
```

## 8. 주의사항 / 함정 (Pitfalls)

1. **항상 `id`를 전달하라.** 모든 호스트 호출의 첫 번째 인자는 훅에서 받은 액세스 키이다. 없으면 조용히 무시된다.
2. **권한 거부는 조용히 무시된다.** `editDisplay` 모드에서 `setChat`을 호출해도 오류가 발생하지 않고 무시된다. 쓰기가 성공했다고 가정하지 마라.
3. **취소하려면 리터럴 `false`를 반환하라.** `nil`이나 `0`이 아닌 오직 `false`만이 전송을 중지시킨다.
4. **`listenEdit` 콜백은 반드시 값을 반환해야 한다.** 수정되지 않았더라도 `return value`를 명시하라. `nil`을 반환하면 체인이 끊어진다.
5. `useMultimodal=true`를 사용하면 텍스트에서 인레이 마커(`{{inlay...}}`)가 제거된다. 이미지는 모델로 전송되지만, 텍스트 자체에서 해당 마커는 빈 문자열로 바뀐다.
6. `setState`/`getState`는 내부적으로 키 앞에 `__`를 붙인다. `getChatVar`와 혼용할 때 이름 충돌 및 동작 방식에 유의하라.
7. **`request`의 제약이 매우 엄격하다.** GET 전용, 120자 제한, HTTPS, 차단된 도메인, 분당 5회 제한 등을 명심하라. 헤더 설정이나 POST는 불가능하다.
8. `generateImage`는 실패 시 구조화된 에러가 아닌 `"Error: Image generation failed"`라는 리터럴 문자열을 반환한다.
9. **모드당 하나의 엔진이 영구적으로 실행된다.** 한 모드에서 설정한 전역 변수는 소스 코드가 바뀌지 않는 한 다음 호출에도 유지된다. 캐싱에 유용하지만, 서로 다른 모드 간의 상태 공유에는 사용할 수 없다.
10. 래퍼 레이어가 코드 앞에 약 150줄을 삽입한다. 오류 추적(Traceback) 시 표시되는 줄 번호에서 래퍼 크기를 빼고 생각하라.
11. **`getDescription`은 그룹 채팅에서 예외를 발생시킨다.** 그룹 환경에서 실행될 가능성이 있다면 `pcall`로 감싸라.
12. 인덱스가 1로 시작하지 않는 Lua 배열을 `json.encode`하면 테이블(객체)로 취급되어 `{}`가 생성된다. 항상 인덱스 1부터 사용하라.
13. `os`, `io`, `package` 모듈에 접근할 수 없다. 외부 파일 시스템이나 프로세스 기능은 제공되지 않으며 오직 이 문서의 함수만 사용 가능하다.
14. 스트리밍 모드(`streaming=true`)라도 호출이 완료된 후에 전체 텍스트가 한 번에 반환된다. 청크 단위 콜백은 스크립트 단에서 지원되지 않는다.
15. `onInput`과 `onOutput`은 메시지를 직접 교체할 수 없다. 방금 추가된 메시지를 수정하려면 `setChat`을 사용하거나, 애초에 변환을 목적으로 설계된 `listenEdit` 훅을 사용하라.
16. Python 지원(`type: 'py'`)도 존재하지만 API 표면이 완전히 다르다. 이 문서는 Lua 스크립팅 전용이다.
17. `callListenMain`, `async`, `json` 등 래퍼 헬퍼 이름을 재정의하지 마라. 시스템 동작을 망가뜨릴 수 있다.
18. `cbs(value)`는 현재 캐릭터 문맥에서 파서를 실행한다. `cbs("{{getvar::hp}}")`처럼 Lua 내에서 템플릿을 렌더링할 때 사용하라.
